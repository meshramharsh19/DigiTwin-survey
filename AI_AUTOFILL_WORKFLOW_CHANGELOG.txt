Property form document auto-fill change log

Goal
   - Remove Gemini dependency and make scanned property form autofill work locally in the browser.
   - Keep manual form filling available when OCR cannot understand the document clearly.

What was implemented
   - Added a compact upload button at the top of the Main Property Assessment Entry modal.
   - Added a local OCR pipeline so users can upload a scanned property form image or PDF.
   - Added live preview of extracted text and extracted draft values.
   - Added a fallback manual-entry hint so users can skip upload and fill the form normally.

Libraries / tools used
   - Tesseract.js for image OCR in the browser.
   - PDF.js (`pdfjs-dist`) for PDF text extraction and PDF page rendering.
   - React hooks (`useState`, `useEffect`, `useRef`) for upload state, OCR state, and file picker control.
   - Regex-based parsing for mapping OCR text into form fields.

How the flow works now
   - User uploads a scanned property image or PDF.
   - The browser reads the file locally.
   - PDF text is extracted first.
   - If PDF text is weak or missing, OCR runs on the image/page.
   - The extracted text is cleaned and mapped into the property form fields.
   - The user reviews the prefilled data and then saves the form.
   - If OCR cannot read a field, the user fills it manually.

Implementation notes
   - PDF.js worker source must be configured in the frontend or PDFs will fail with workerSrc errors.
   - Greedy regex parsing was replaced with label-boundary parsing so values do not spill into the next field.
   - Build validation was run after each major change and the frontend production build passes.

Validation results
   - Frontend build: successful.
   - Syntax checks: successful.
   - Final OCR flow: local-only, no Gemini quota dependency.

Configuration note
   - REACT_APP_API_BASE_URL is still useful if the backend is not on localhost:5001.
   - Gemini is not required for the current autofill implementation.
